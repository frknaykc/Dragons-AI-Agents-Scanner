## Documented surfaces and evidence

- **Antigravity:** [rules and precedence](https://antigravity.google/docs/rules-workflows), [skills](https://antigravity.google/docs/skills), [MCP](https://antigravity.google/docs/mcp). Directory rules (`AGENTS.md`, `GEMINI.md`, `.agents/rules/*.md`), workspace `.agents/skills/` (legacy `.agent/skills/`) and global `~/.gemini/config/skills/` are documented. The MCP guide describes `mcpServers` with `command`/`serverUrl` and `disabled`, and mentions IDE `mcp_config.json` without an absolute path; no IDE/CLI path is inferred. Dragons has **no Antigravity-specific registry/spec**. Generic `AGENTS.md` may be scanned but is unattributed. `.agents` and `.gemini` are shared across products; a unique Antigravity install identity, effective configuration and safe root attribution remain **NOT VERIFIED**. No speculative adapter was added.
- **Claude Code:** [settings scopes](https://code.claude.com/docs/en/settings), [MCP](https://code.claude.com/docs/en/mcp), [skills](https://code.claude.com/docs/en/skills). `~/.claude/settings.json`, `.claude/settings.json`, `CLAUDE.md`, skills, project `.mcp.json` and user `~/.claude.json` are documented. Dragons discovers the `.claude` subset and generic MCP config, but does not model all precedence, plugin manifests or per-product `.claude.json` MCP ownership. The generic project file is not agent-attributed.
- **Hermes Agent:** [configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration), [profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles), [MCP schema](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference). `~/.hermes/config.yaml`, `SOUL.md`, profile-specific config, skills, memories and cron state are documented; `mcp_servers` uses `command`/`url`/`enabled` and optional trust/TLS policies. Dragons's path discovery is bounded but does **not** normalize this snake_case MCP schema or derive effective profile precedence. Plugin configuration and dynamic profile identity beyond the current bounded selection are not asserted.
- **Cline:** [global/project config layout](https://docs.cline.bot/getting-started/config), [MCP](https://docs.cline.bot/mcp/mcp-overview). `~/.cline/data/settings/cline_mcp_settings.json` and `global-settings.json` are now explicitly selected; `providers.json` (credentials), session histories and databases are excluded. `.cline/{rules,skills,workflows,hooks,plugins,agents}` and project `.clinerules` / `.agents/skills` are documented, but only part of these surfaces are selected. `mcpServers` maps via the existing parser; actual installed MCP settings were not observed. `~/.cline/mcp.json` is a pre-existing Dragons alias, not a claim that it is the current canonical CLI path.
- **Cursor:** [rules](https://cursor.com/docs/context/rules), [skills](https://cursor.com/docs/skills), [MCP](https://cursor.com/docs/mcp), [plugins](https://cursor.com/docs/plugins). `.cursor/rules/` supports `.md` and `.mdc`; Dragons recognizes only Markdown. Skills and plugin packages are not mapped, and global user rules may live in editor-managed settings. `mcp.json` uses `mcpServers`, with remote URLs and interpolation; no assertion of effective enterprise/dashboard policies.
- **Codex:** [configuration](https://developers.openai.com/codex/config-reference), [customization](https://developers.openai.com/codex/concepts/customization), [skills](https://developers.openai.com/codex/skills). `~/.codex/config.toml`, repo `AGENTS.md`, `.agents/skills` and plugin packaging are documented. Dragons parses TOML and discovers its `.codex` subset but does not interpret `mcp_servers`, shared `.agents` skill ownership, plugin packages or layered precedence. Generic `AGENTS.md` is not Codex-only.
