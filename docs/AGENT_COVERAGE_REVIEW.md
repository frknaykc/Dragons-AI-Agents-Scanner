## Documented surfaces and evidence

- **Antigravity — PARTIAL feasibility, no adapter:** Google [rules](https://antigravity.google/docs/rules-workflows), [skills](https://antigravity.google/docs/skills) and [MCP](https://antigravity.google/docs/mcp) describe global `~/.gemini/GEMINI.md`, workspace `.agents/rules/`, skills and `mcpServers` (including `serverUrl`/`disabled`). These are official artifact surfaces, but `.agents` and `.gemini` are shared across products; an agent-specific persistent MCP file path and safe install identity are not established. **Do not claim Antigravity ownership from these directories.** No adapter is added; discovery stays NOT VERIFIED. Next milestone requires an official disambiguating product marker, edition/version and IDE config location.
- **Claude Code:** [MCP scopes and precedence](https://code.claude.com/docs/en/mcp#mcp-installation-scopes), [settings](https://code.claude.com/docs/en/settings), [skills](https://code.claude.com/docs/en/skills). Project-root `.mcp.json` and user-home `~/.claude.json` now have Claude attribution when explicitly selected; `.claude/settings.json` does **not** confer MCP ownership. `mcpServers` stdio/HTTP/SSE with command/args/env and URL/header references enter the static inventory; malformed/unsupported entries are diagnosed. `~/.claude.json` contains other sensitive state: only its top-level and explicitly matching project `mcpServers` maps are exposed to structured analysis; raw signature matching of unrelated private state is excluded (coverage diagnostic). **Local scope:** on an explicit project scan, the matching `projects[absolute path].mcpServers` entry in `~/.claude.json` is projected; other projects are ignored and local names override user names in that file, with `local`/`user` provenance retained per server. This is a static *definition* projection, not approval or connection. **Gaps:** `disabledMcpServers`/`disabledMcpjsonServers`, project approvals, plugin servers and cross-file effective scope precedence (`local > project > user`) are not evaluated. User/project config scopes remain distinct in artifact provenance. JSON line numbers are not inferred. Tests: `tests/test_p1_agent_coverage.py`; real install NOT VERIFIED.
- **Hermes Agent:** [configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration), [profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles), [MCP schema](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference). Existing `~/.hermes/config.yaml` discovery now statically maps documented `mcp_servers` local `command`/`args`/`env` and remote `url`/`headers`, respecting `enabled: false` and rejecting malformed/unsupported entries. Secret values are not retained in config entries, env or header references; YAML key lines are preserved. Project-level Hermes config is NOT VERIFIED; active profile merge, HTTP TLS/trust settings, runtime status and effective precedence are not inferred. The former **64-artifact limit** was reached in the earlier metadata-only observation. The 2026-10-28 coverage change removes that cumulative default; [synthetic validation](SCAN_COVERAGE_VALIDATION.md) reaches 1,000 skills with bounded traversal buffers. This is not a new real-install observation. Tests: `tests/test_p1_agent_coverage.py`; real artifact scan NOT VERIFIED.
- **Cline:** [global/project config layout](https://docs.cline.bot/getting-started/config), [MCP](https://docs.cline.bot/mcp/mcp-overview). `~/.cline/data/settings/cline_mcp_settings.json` and `global-settings.json` are now explicitly selected; `providers.json` (credentials), session histories and databases are excluded. `.cline/{rules,skills,workflows,hooks,plugins,agents}` and project `.clinerules` / `.agents/skills` are documented, but only part of these surfaces are selected. `mcpServers` maps via the existing parser; actual installed MCP settings were not observed. `~/.cline/mcp.json` is a pre-existing Dragons alias, not a claim that it is the current canonical CLI path.
- **Cursor:** [rules](https://cursor.com/docs/context/rules), [rules format clarification](https://cursor.com/docs/rules), [skills](https://cursor.com/help/customization/skills), [MCP](https://cursor.com/docs/mcp). Project `.cursor/rules/**/*.mdc` is discovered as an instruction artifact; bounded YAML frontmatter (`description`, `globs`, `alwaysApply`) is separated from the Markdown body and *not* evaluated as actual runtime activation. Project/user `.cursor/skills/**/SKILL.md` is selected from Cursor-owned roots; shared `.agents/skills` is not attributed by existence alone. Global rules in editor-managed settings, remote rules, plugins and runtime activation are NOT VERIFIED. Official pages conflict on bare `.md` under rules (`docs/context/rules` shows `.md`; `docs/rules` calls it ignored); this milestone only asserts `.mdc`. Tests: `tests/test_p1_agent_coverage.py`; real install NOT VERIFIED.
- **Codex:** [MCP guide](https://developers.openai.com/codex/mcp), [config reference](https://developers.openai.com/codex/config-reference), [official config schema at `e89b7c4`](https://github.com/openai/codex/blob/e89b7c442c0433ad5167e72a5a25bb6d0712766a/codex-rs/core/config.schema.json). User `~/.codex/config.toml` and explicit project `.codex/config.toml` (the latter loaded by Codex only in trusted projects) select `[mcp_servers.NAME]` local `command`/`args`/`env` or remote `url`/`http_headers`/`env_http_headers`/`bearer_token_env_var`; `enabled = false` is excluded. TOML server table lines are retained for simple unquoted names; other TOML locations have file-only provenance. TOML duplicate table rejection is inherited; arbitrary tables are not MCP servers. **Gaps:** trust, scope merges/overrides, advanced auth and active runtime status are not inferred; `.agents` ownership is not assumed. Tests: `tests/test_p1_agent_coverage.py`; real install NOT VERIFIED.
