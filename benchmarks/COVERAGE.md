# Built-in coverage inventory

`uv run --offline python -m scripts.coverage_inventory --format json` emits stable JSON. An optional positional manifest path overrides `benchmarks/corpus/manifest.json`. A missing manifest leaves benchmark fields false; an invalid or unknown-ID manifest fails rather than reporting guessed coverage. This command reads source, registry metadata and the manifest, **not** artifact contents; it does not run a scanner, model, OSV request, or threat-intel update.

`ids` are built-in detector/rule/signature metadata plus static scanner finding-emission sites. `summary.built_in_ids` includes the opt-in semantic, OSV, and threat-intel IDs; `summary.default_uncovered_count` excludes those. External signature packs define IDs at runtime and are **not enumerable** in this built-in total. Each row records implementation origin and execution group separately from coverage.

Coverage is evidence of an **assertion**, not proof the scanner passed it. `benchmark_positive` means the manifest expects the ID in at least one case. `development` and `holdout` indicate positive support by split. `benchmark_hard_negative` requires explicit per-ID `expected_absent` in a case; a benign case without an ID is not automatically a hard negative for all IDs. `occurrence_assertion` requires structured `expected_findings` with a matching ID and location (`artifact` or `line`). `source_sink_assertion` requires at least one explicitly asserted `source` or `sink` (including `null`). `graph_path_assertion` requires a structured `path_edges`, `path_nodes`, `flow_edges` or `flow_nodes` assertion. `graph_path_applicable` marks direct graph/correlation emitters; false does not rule out graph enrichment elsewhere. `unit_positive` and `unit_negative` are null (unknown): existing test names and incidental test literals are not reliable per-ID assertion metadata. False benchmark fields mean *not explicitly evidenced*, not necessarily untested.

The inventory does not claim to satisfy missing support and does not fabricate corpus fixtures. Treat uncovered IDs as a worklist, not a quality score. Schema changes in the benchmark should be mirrored here only after assertions have well-defined meaning.
