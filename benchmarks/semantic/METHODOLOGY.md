# Semantic benchmark methodology (development split)

This is a **separate evaluation harness**, not a scanner rule or a modification to benchmark v2. It loads `corpus/manifest.json` alongside this file. The manifest has `version: "1.0"` and cases with `{id, artifact, semantic_id, expected, class, split}`, plus optional `expected_finding` for positive cases. `artifact` is a local corpus-relative `AGENTS.md` or `mcp.json` file; `split` is currently `development`. `expected` is a boolean about the **specified semantic ID**, not every finding on the artifact. Use `class: "hard-negative"` (also accepts `hard_negative`) for negative cases crafted to resemble positives. Unique IDs and safe, present, discoverable, non-symlink paths are required. Corpus text is untrusted and never executed, imported, installed, sourced, or followed.

From the repo root (with locked dependencies already available):

```sh
uv run --offline python -m scripts.semantic_benchmark benchmarks/semantic/corpus/manifest.json --format json
uv run --offline pytest -q tests/test_semantic_benchmark.py
```

Default: **offline**, `--repeats 3`. Each case/repeat runs the real baseline scanner without semantic provider and calls the real `select()` on the baseline-discovered/parsed artifacts and findings. Baseline candidate selection may differ from the scanner's internal selection if another preprocessing stage enriches documents; the provider run also records its actual selected/analyzed counts. No fake-model detections or inferred semantic quality appear in the default report. Fields `provider_quality` and `measurements_4_to_10` explicitly say **NOT MEASURED** without opt-in.

A real provider requires **both** `--provider-url URL --model NAME`, e.g. a deliberately chosen OpenAI-compatible `/v1/chat/completions` endpoint. `DRAGONSCAN_SEMANTIC_API_KEY` is read from the environment by the existing provider (never pass credentials in the URL). This sends scanner-selected, redacted corpus excerpts off-host unless the specified endpoint is local. Do not run a provider benchmark without authorization to send the corpus. No redirects or provider/network calls occur by default. There are no dependencies beyond the project; tests use fake providers only to verify mechanics and must not be described as accuracy/quality results.

## Denominators and judgments

All counts are per **case × repeat**, grouped by semantic ID. Positives, ordinary negatives, and hard negatives are case counts (not multiplied by repeats). `positive_exposure` is the number of baseline-successful positive repeats. `candidate_recall_proxy` is the fraction of these where `select()` retained **any** candidate with the ID's category in the case artifact; no ground-truth candidate is supplied, so this is eligibility, **not** evidence-localized recall. `static_tp_proxy` counts baseline-successful positive repeats with at least one mapped deterministic static finding in that artifact. The overlap map matches semantic enrichment's category-to-static-ID map. `deterministic_finding_positive` counts *any* static finding on positive cases. Neither number proves that the static finding identified the labeled intent. Baseline failures are excluded from these denominators.

With a provider, each repeat reruns baseline and scanner with semantic enabled; only complete provider runs count toward provider confusion counts. A semantic hit for the specified ID is a new `DRAGON-SEM-*` finding with matching ID, category, artifact, or an annotation on a mapped static finding with matching semantic category and artifact. Wrong ID/category/artifact does not count as a correct hit and appears as `mismatched_outputs`. The `static_unchanged` comparison covers occurrence, category, artifact, line, and severity for static findings between baseline and semantic runs. For new findings, `candidate_location_match` checks finding artifact/line against the referenced selected candidate; `new_severity_policy_valid` checks the semantic severity policy (low/medium), **not** a truth-label severity. Annotation comparisons preserve static ID/category/artifact/line/severity. Unless a case supplies explicit `expected_finding` fields, these checks do not validate localization or severity against ground truth.

For **positive** cases, a detected hit with any optional occurrence expectation satisfied is TP, otherwise FN; for **negative/hard-negative** cases, a hit is FP, otherwise TN. The optional `expected_finding` supports only explicitly given `id`, `category`, `artifact`, `line`, `evidence_contains`, `severity`, using benchmark v2's `_differences` semantics. A false occurrence check is a miss, not a correct hit. Scanner semantic `evidence` is boilerplate rather than quoted source text, so evidence checks verify output shape, **not model grounding**; provider rationale is not independently truth-validated. The report stores only pass/fail of the occurrence assertion, not expectation literals. `additional_tp` is a new semantic finding on a positive without the static overlap proxy. `duplicate_or_enrichment_tp` is a semantic hit with static overlap or annotation (these labels can overlap when both outputs occur). A positive miss without an eligible candidate is a `candidate_miss`; an eligible candidate without a correct hit on a complete run is a `provider_miss` *proxy*. Provider failures, schema rejects, budget partials, and other partials are reported separately, excluded from TP/FP/FN/TN and never silently counted as misses. `confidence_by_truth` counts detected high/medium/low buckets against positive/negative labels and correct/incorrect occurrence judgments (including negative hits); `absent` counts non-detections, not a model confidence. Multiple buckets can be present per repeat. Confidence is a provider label, **not a calibrated probability**. `other_semantic_ids_for_review` exposes unlabelled categories without assuming they are false positives. Severity and candidate/location consistency remain separate from confidence/truth.

`stable-correct` means **every complete repeat** agrees with the expected boolean and has no mismatched output; `stable-incorrect` means none do; mixed repeats are `flaky`. Any incomplete repeat makes the case `inconclusive`. No provider makes stability **NOT MEASURED**. These describe repeated observed behavior, not statistical guarantees. No request body, provider response, raw diagnostics/errors, snippet, rationale, key or evidence is persisted in results; JSON includes manifest metadata, aggregate counts, coarse status, provider identity/model/version, and finding attributes without artifact content. The manifest's artifact names are copied to reports; avoid sensitive names. Review before distributing results.

`provider_recall_given_candidate` uses complete positive repeats that had a category-eligible baseline candidate as its denominator; it remains an eligibility proxy, not a verified provider-request trace for that exact passage. `end_to_end_semantic_recall` uses all complete positive repeats. `semantic_only_fp` / `semantic_only_fn` exclude cases with mapped static-overlap proxies; they are not population-level model error estimates. A case with any partial provider/schema/budget outcome is excluded from all these provider-quality ratios. The `confidence_by_truth` correctness bucket also requires explicitly asserted occurrence fields when present; high/medium/low represent labels, not probabilities. Scanner-suppressed low-confidence output is not observed as a finding bucket.

A fake provider in integration tests verifies control flow, repeat isolation, correct failure accounting and offline safety only; **do not publish its TP/FP counts as model performance**. Development-only results are exploratory and must not be represented as held-out generalization. Report corpus coverage, provider/model and its parameters, run count, failure rates, stability and class balance alongside any real-provider numbers.
